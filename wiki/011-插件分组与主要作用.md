# 011 · 插件分组与主要作用

> DeepSeek Harness 源码专题 · 第 11 篇
> 接 [002 · 目录地图](./002-目录结构与架构图.md) · [008 · dsh-base](./008-dsh-base挂载了哪些插件.md) · [006 · Presets](./006-四种Agent-Presets对比.md) · 流程见 [000](./000-当前项目开发流程.md)
> 主线：按架构层把 `packages/*/*` 分组，一包一句说明主要作用

仓库里每个产品包几乎都是 **Cordis 插件**（或被插件消费的库）。包很多，按目录字母扫会迷路。
本篇按 **读源码优先级** 压成九层，层内再按 `packages/<group>/` 列包——与 [002](./002-目录结构与架构图.md) 的分层图同向，但粒度到每个包。

权威映射仍以 [`packages/README.zh.md`](../packages/README.zh.md) 与各组 README 为准；本篇是跟读用的速查表。

| 事实 | 含义 |
|---|---|
| 包路径 | `packages/<group>/<pkg>/` → npm `@deepseek-ai/dsh-<…>` |
| 能力缝 | 完整能力 = Service Definition + Provider + Consumer（常是 `tool-*`） |
| Host vs Agent | Host 平面由 profile / bundle patch 挂；Agent 平面由 preset 的 `agent.cordis.yml` 挂（见 [009](./009-cordis.patch与agent.cordis的区别.md)） |
| 实际挂了哪些 | 不是「仓库有就挂」；`web`/`headless` 等看 [008](./008-dsh-base挂载了哪些插件.md) + profile patch |

一句话：

> **找能力先定层与组，再打开该组 README；改默认行为优先改 patch / preset，而不是 fork 整组包。**

---

## 九层总览

```text
① core                    产品脊柱（Session / prompt / tools / Agent / loop）
② session · query · …     会话与数据平面
③ credentials · interaction · …   配置、身份、人机协作
④ llm · context · preset · …      模型上下文与循环卫生
⑤ fs · shell · subagent · …       执行世界（能力缝）
⑥ extensions · hooks      运行时自改与外部 hooks 桥
⑦ bundle · boot           组合与启动
⑧ api · host · client · sdk · acp 应用面
⑨ experimental · util · … 实验与支持
```

| 层 | 何时先读 |
|---|---|
| ①②④ | 跟一次对话、改模型可见行为 |
| ⑤ | 换执行世界、加工具、沙箱 |
| ③ | 权限 / 密钥 / 斜杠命令 |
| ⑦⑧ | 启动 profile、改 Web UI、接 SDK |
| ⑥⑨ | 自改运行时、原型、写测试 |

当前 checkout 约 **255** 个包、**50** 个组（另有空的 `examples/` 等非包目录不列入下表）。

## ① 产品脊柱

几乎所有 profile 都踩在这；改循环 / 工具 / 提示先来这里。

### `core/` · 产品 API 脊柱：Session、prompt、tools、Agent、agent-loop

| 包 | 主要作用 |
|---|---|
| `agent` | Agent 句柄：创建/恢复、followup、注入上下文、取消与等待 |
| `agent-default-model` | 部署默认模型选择（provider / model / reasoning） |
| `agent-loop` | 默认 Agent 循环：turn/step、组请求、流式、工具调度 |
| `agent-tool-presentation` | Preset 选择工具呈现形态（native / PTC 等） |
| `scope` | 按 agent 隔离的注册作用域库（无 Cordis 服务键） |
| `session` | 追加写 Session 事件日志——模型可见事实的唯一真源 |
| `system-prompt` | 组装系统提示段与工具 schema |
| `tools` | 工具注册与执行管线（策略 / 守卫 / 超时入口） |

## 能力缝怎么读一行

多数执行类组会出现三类名字，对照即可：

| 名字线索 | 角色 | 例子 |
|---|---|---|
| 与组同名、无后缀 | Service Definition（`ctx.<seam>`） | `fs`、`shell`、`llm`、`web` |
| `*-local` / `*-sandbox` / 厂商名 | Provider（可换后端） | `fs-local`、`bash-sandbox`、`llm-deepseek` |
| `tool-*` / `command-*` | Consumer（模型或人入口） | `tool-fs`、`command-compact` |
| `ui-*` | Client 展示面 | `ui-chat`、`ui-tool` |

扩展产品时：**Consumer 依赖 Definition，不要绑死某个 Provider**。
